# PRD 0007 — The `playset` command: from a Setlist to a shared Setlist Playlist

Status: Approved
Slice: 7
Depends on: 0001, 0002, 0003, 0004, 0005, 0006
Module: src/core/run and src/cli

## Problem

Each part of Playset now works on its own. PRD 0001 reads the setlist id from a setlist.fm link. PRD 0002 turns a **Setlist** into **Performances**, noted songs, a Tape list and **Show** details. PRD 0003 finds the **Match** for one Performance, or reports a **Miss**. PRD 0004 gets a Spotify access token. PRD 0005 fetches a Setlist by id, or finds an **Artist**'s **Latest Setlist**. PRD 0006 works out the playlist name and description, checks for playlists with the same name, and creates the **Setlist Playlist**.

A concert-goer still can't use any of it. Nothing joins these steps into one run. Nothing decides whether the input is a link or an Artist name. Nothing asks which **Tapes** to keep, shows what will be created before it is created, asks for confirmation, or prints the Misses and the share link. Nothing turns errors into short messages and exit codes. A future web or mobile front-end will need the same run, so the run must not depend on a terminal.

## Goal

One `playset <setlist.fm link | Artist name…>` command turns a Setlist into a Setlist Playlist. The command:

- shows the Show;
- asks about each Tape;
- logs in to Spotify;
- finds a Match for each kept Performance, with progress;
- previews every Performance with its Match or Miss, the songs left out, the playlist name, the privacy setting and any playlist with the same name;
- asks for confirmation, then creates the playlist;
- lists the Misses and always ends with the share link.

The whole run sits in the core and works without a terminal. Every question and every service is supplied by the front-end. The command-line front-end only reads arguments, asks questions in the terminal, prints, and sets the exit code.

## Non-goals

- **No web or mobile front-end** and no backend proxy for the setlist.fm key.
- **No setup wizard.** Playset never writes the setlist.fm API key, the Spotify client id or any other setting. Missing settings are reported with the hints from PRD 0004 and PRD 0005.
- **No editing of existing playlists.** Playset never adds to, renames, replaces or deletes a playlist. A playlist with the same name only causes a warning (PRD 0006 AC-10). A partly created playlist is left as it is.
- **No parallel matching.** Performances are matched one at a time, in played order.
- **No manual Match choice.** The user can't pick a different track, retry a Miss, or edit the list in the preview. The only choices are yes or no to each Tape and to the final confirmation.
- **No colour or output-format options.** No `--color`/`--no-color`, `--json` or `--quiet`.
- **No non-interactive mode beyond the flags.** `--tapes`, `--no-tapes` and `--yes` skip their questions. Choosing between several Artists still needs a terminal. Without a terminal, the user can give a setlist.fm link instead.
- **No search queries in the output.** A Miss is printed with its title, Artist and Original Artist only. The searches recorded by PRD 0003 are not printed.
- **No token refresh during a run.** One access token is used for the whole run. A token that expires during a very long run causes a Spotify error like any other.
- **No changes to module behaviour.** Link reading, Performance rules, matching rules, login, setlist.fm lookups, naming and creation work exactly as PRDs 0001–0006 describe. This PRD only puts them together and presents them.
- **No medley splitting and no snippets in the playlist.** As in PRD 0002, these are only listed as "not added".
- **No logout, account switching or cache-clearing commands.**

## User stories

- As a concert-goer, I want to type `playset arctic monkeys` and get a Setlist Playlist of the Latest Setlist, so that I can learn the songs before the Show.
- As a concert-goer, I want to paste the setlist.fm link of a specific Show instead, so that I get exactly that Setlist.
- As a concert-goer, I want to be asked which Artist I mean when the name is ambiguous, so that I don't get a tribute band's Setlist.
- As a concert-goer, I want to decide for each Tape whether it goes in, or decide for all of them with a flag, so that intros and outros only appear when I want them.
- As a concert-goer, I want to see every Performance with its Match, and every Miss, before anything is created, so that I can stop if it looks wrong.
- As a concert-goer, I want a warning when I already have a playlist with that name, so that I don't end up with copies by accident.
- As a concert-goer, I want a dry run that shows the preview without creating anything, so that I can check the result first.
- As a concert-goer, I want the share link printed at the end every time a playlist is made, even if something failed part-way, so that I can open or share it right away.
- As a concert-goer, I want short error messages that tell me what to do, not stack traces, so that I can fix setup problems myself.
- As a front-end developer, I want the whole run in the core, with every question and service supplied by the caller, so that a web or mobile front-end can reuse it and tests can run it with fakes.

## Acceptance criteria

Some words used below:

- **Input**: the command-line arguments that are not flags, joined with single spaces.
- **Kept Performances**: the Performances that will be matched. These are every Performance from PRD 0002 that is not a Tape, plus each Tape the user opted into, in played order.
- **Exit code**: 0 for success, a dry run, or a declined confirmation; 1 for a runtime error (including "nothing to add" and "every Performance is a Miss"); 2 for a usage error; 130 for a cancellation (Ctrl-C).
- **Usage line**: `Usage: playset [options] <setlist.fm link | Artist name...>`.

Unless an AC says otherwise, "message" means text printed to the standard error stream, and every other output goes to the standard output stream. Wording may differ from the Examples, but every fact an AC names must be present.

### Input and usage

- **AC-1** — Given one or more arguments that are not flags and do not look like a setlist.fm link (PRD 0001 AC-15/AC-16), when `playset` runs, then the arguments joined with single spaces are used as the Artist name. The Artist lookup and Latest Setlist search of PRD 0005 run with that name. `playset Arctic Monkeys` and `playset "Arctic Monkeys"` behave the same.
- **AC-2** — Given exactly one argument that looks like a setlist.fm link and from which a setlist id can be read (PRD 0001 AC-1 to AC-9), when `playset` runs, then that Setlist is fetched by id (PRD 0005 AC-10). No Artist search is sent and no Artist question is asked.
- **AC-3** — Given an argument that looks like a setlist.fm link but is rejected by PRD 0001 (reason **not-a-setlist-page** or **missing-id**), when `playset` runs, then PRD 0001's message for that reason is printed with the usage line, the exit code is 2, and no network request is made.
- **AC-4** — Given no input (no arguments, or only whitespace), or more than one argument where at least one looks like a setlist.fm link, when `playset` runs, then a message saying what is wrong is printed with the usage line, the exit code is 2, and no network request is made.
- **AC-5** — Given both `--tapes` and `--no-tapes`, or any option Playset doesn't know (for example `--publik`), when `playset` runs, then a message naming the problem is printed with the usage line, the exit code is 2, no question is asked and no network request is made.
- **AC-6** — Given `--help`, when `playset` runs, then a help text is printed. It contains the usage line, says the input can be a setlist.fm link or an Artist name, and lists `--tapes`, `--no-tapes`, `--yes`, `--public`, `--dry-run`, `--help` and `--version`, each with a one-line description. The exit code is 0 and no network request is made. Given `--version`, then only Playset's version number (`0.1.0` for this release) is printed, the exit code is 0, and no network request is made.
- **AC-7** — Given flags written before, after or between the words of the input, when `playset` runs, then they are recognised the same way, and only the arguments that are not flags form the input.

### Choosing the Artist

- **AC-8** — Given an Artist name for which PRD 0005 asks its chooser (no exact match, or several exact matches), when `playset` runs, then the user is shown one select list with the candidates in setlist.fm's order (at most 10). Each candidate is shown as its name followed by its disambiguation text in parentheses, or as its name alone when there is none. The Artist the user picks is used for the Latest Setlist search. Given PRD 0005 chooses the Artist automatically, then no select list is shown.

### The Show

- **AC-9** — Given the Setlist has been fetched, when it is turned into Performances (PRD 0002), then a Show line is printed before any Tape question and before any Spotify login. It contains the Artist name, the date (`YYYY-MM-DD`), the venue and the city, followed by the setlist.fm URL and the number of Performances and Tapes.
- **AC-10** — Given a Setlist with no Performances (for example an announced Show fetched by link), when `playset` runs, then the Show line is printed, then a message saying the Setlist has no Performances yet. The exit code is 1. No Tape question is asked and no Spotify request or login is made.
- **AC-11** — Given Show details whose playlist description would be longer than PRD 0006 allows (PRD 0006 AC-3), when `playset` runs, then the run stops after the Show line with PRD 0006's message and exit code 1, before any Tape question and before any Spotify request or login.

### Tapes

- **AC-12** — Given a Setlist with Tapes, and neither `--tapes` nor `--no-tapes`, when `playset` runs, then one yes/no question is asked for each entry of the Tape list (PRD 0002 AC-5), in played order. A Tape played twice is asked about twice. Each question shows the Tape's title and, if it is a Cover, its Original Artist. The default answer is No. A Tape answered Yes is a kept Performance at its played position. A Tape answered No is left out.
- **AC-13** — Given `--tapes`, when `playset` runs, then every Tape is a kept Performance and no Tape question is asked.
- **AC-14** — Given `--no-tapes`, when `playset` runs, then every Tape is left out and no Tape question is asked.
- **AC-15** — Given a Setlist with no Tapes, when `playset` runs, then no Tape question is asked, whatever the flags.
- **AC-16** — Given `--yes`, when a Setlist has Tapes, then the Tape questions are still asked (unless `--tapes` or `--no-tapes` is given). `--yes` only skips the final confirmation.
- **AC-17** — Given there are no kept Performances after the Tape decisions (every Performance was a Tape that was left out), when `playset` runs, then a message says there is nothing to add, the exit code is 1, and no Spotify login or request is made.

### Spotify login

- **AC-18** — Given there is at least one kept Performance, when `playset` runs, then a Spotify access token is requested once (PRD 0004), after all Tape decisions and before any Spotify search. That one token is used for every search, the duplicate check and the creation. No Spotify request of any kind is made before the Tape decisions are complete.
- **AC-19** — Given PRD 0004 needs a full login, when it asks the front-end to show the authorize URL, then the CLI tries to open it in the default browser (`open` on macOS, `xdg-open` on Linux, `start` on Windows). It always prints the URL with a line saying to open it if the browser did not open. It then waits for the login to finish.
- **AC-20** — Given the browser can't be opened (the command is missing or fails), when a full login is needed, then the URL is still printed, no error is shown, and the run continues to wait for the login.
- **AC-21** — Given PRD 0004 returns a valid cached or refreshed token without a full login, when `playset` runs, then no browser is opened and no authorize URL is printed.

### Matching

- **AC-22** — Given the kept Performances, when matching runs, then each kept Performance is matched with PRD 0003 exactly once, in played order. The next one starts only after the previous one has finished. A song played twice is matched twice.
- **AC-23** — Given N kept Performances, when matching runs, then progress is shown for each Performance as `n/N` with its title, for n = 1 … N in order.
- **AC-24** — Given a Spotify search fails during matching (PRD 0003 AC-18, AC-20, AC-21), when `playset` runs, then the run stops with that error's message (AC-38). The exit code is 1, no further search is sent, and no playlist is created.
- **AC-25** — Given every kept Performance is a Miss, when matching finishes, then the Misses are listed (as in AC-36), followed by a message that no Match was found so no playlist was created. The exit code is 1. No confirmation is asked and no create request is sent. This also applies with `--dry-run` and with `--yes`.

### Preview

- **AC-26** — Given at least one Match, when matching finishes, then a preview lists every kept Performance, numbered 1, 2, 3 … in played order. A heading with the Set label (PRD 0002 AC-2: `main`, a named Set, or `Encore n`) is shown before the first Performance of each Set. Each Performance shows its title, a `Tape` marker if it is a Tape, and `Cover of <Original Artist>` if it is a Cover. It then shows either its Match, as `<track name> — <artists joined with ", "> · <album>` with ` (live)` added when the Match is live, or `Miss`.
- **AC-27** — Given noted songs (PRD 0002 AC-9 to AC-11) or Tapes that were left out, when the preview is shown, then a "Not added" section lists them in played order. Each noted song shows its raw name and its reason (`snippet` or `medley`). Each left-out Tape shows its title and `Tape, left out`. Given there are none, the section is not shown.
- **AC-28** — Given the preview, when it is shown, then it also shows the Setlist Playlist name (PRD 0006 AC-1), whether the playlist will be `private` or `public`, the number of tracks (equal to the number of Matches, repeats included) and the number of Misses.
- **AC-29** — Given the duplicate check (PRD 0006 AC-5 to AC-8) finds one or more playlists with the same name, when the preview is shown, then it includes a warning that lists each one with its name and share link, and says a new playlist will be created anyway. Given it finds none, then no warning is shown. The duplicate check runs once per run, after matching.
- **AC-30** — Given a run that reaches the preview, when it runs, then the whole preview, including any duplicate warning, is shown before the confirmation question and before any create request.

### Confirming and creating

- **AC-31** — Given neither `--yes` nor `--dry-run`, when the preview has been shown, then one yes/no question asks whether to create the playlist. The default answer is No. Given the answer Yes, then the Setlist Playlist is created from the Show details and the Matches in played order (PRD 0006 AC-11 to AC-15).
- **AC-32** — Given the user answers No (or accepts the default), when asked to confirm, then no create request is sent, a message says no playlist was created, and the exit code is 0.
- **AC-33** — Given `--yes`, when the preview has been shown, then no confirmation is asked and the Setlist Playlist is created.
- **AC-34** — Given `--public`, when the Setlist Playlist is created, then it is created as public (PRD 0006 AC-12) and the preview says `public`. Without `--public`, it is created as private and the preview says `private`.
- **AC-35** — Given `--dry-run` (with or without `--yes`), when `playset` runs, then everything up to and including the preview happens: Artist choice, Tape questions, Spotify login, matching, duplicate check and preview. After that the Misses are listed (as in AC-36) and a final line says it was a dry run and no playlist was created. No confirmation is asked, no create or add-items request is sent, and the exit code is 0.

### Result

- **AC-36** — Given the Setlist Playlist was created, when the run finishes, then the output shows, in this order: a line with the playlist name and the number of tracks added; then the Misses, if any, each as `<title> — <Artist>`, with ` (Cover of <Original Artist>)` added for a Cover, in played order, under a heading with their count (when there are no Misses, a line says every Performance has a Match); and last, on its own line, the share link (PRD 0006 AC-15). The exit code is 0.
- **AC-37** — Given a Setlist Playlist was created, fully or partly, when the run ends, then its share link is printed, and it is the last line of the standard output stream.

### Errors and exit codes

- **AC-38** — Given any typed error from PRDs 0001–0006 ends the run, when it is reported, then a short message is printed, followed by that error's hint lines if it has any. The exit code is 1, or 2 for the link errors in AC-3. This covers at least: missing setlist.fm API key, missing Spotify client id, invalid auth port, auth port in use, Spotify login declined, other Spotify login errors, Artist not found, no Setlist for the Artist, Setlist not found by id, setlist.fm rate limit, Spotify rate limit, setlist.fm request error, Spotify error, and description too long.
- **AC-39** — Given adding tracks fails after the playlist was created (PRD 0006 AC-20), when the run ends, then a message says the playlist was only partly created and gives the number of tracks added out of the total. The share link is still printed as the last line of standard output (AC-37). The exit code is 1.
- **AC-40** — Given any error, when it is reported and `PLAYSET_DEBUG` is not set to `1`, then no stack trace and no internal error class name is printed. Given `PLAYSET_DEBUG=1`, then the error's details, including the stack trace and any underlying cause, are printed after the message on the standard error stream.
- **AC-41** — Given an error that is not one of the typed errors in AC-38, when it ends the run, then one line says something went wrong and gives the error's message, and a hint says to set `PLAYSET_DEBUG=1` for details. The exit code is 1.
- **AC-42** — Given the user presses Ctrl-C at any question (Artist choice, a Tape question, or the confirmation) or while Playset waits for the Spotify login, or the Artist chooser is cancelled (PRD 0005 AC-17), when the run ends, then one line says `Cancelled.`, no stack trace is printed, no create request is sent, and the exit code is 130.
- **AC-43** — Given any run, with or without `PLAYSET_DEBUG=1`, when anything is printed, then the output never contains the setlist.fm API key, the Spotify access token or the Spotify refresh token.

### Running the core without a terminal

- **AC-44** — Given a fake setlist.fm, a fake Spotify (token, search, duplicate check and create), and fake answers for the Artist choice, each Tape question and the confirmation, when a whole run is carried out through the core, then it completes with no terminal and no real network access. The front-end is asked for each of those answers and for showing the authorize URL, and is given the Show, each progress step, the preview, the Misses and the result. The core's outcome tells a front-end whether the run created a playlist (with its share link and track count), was a dry run, was declined, or had nothing to create.
